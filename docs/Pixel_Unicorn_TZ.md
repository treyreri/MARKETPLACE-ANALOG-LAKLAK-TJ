# Техническое задание --- Pixel Unicorn Marketplace

## 1. Концепция проекта

**Рабочее название:** Pixel Unicorn

Полноценный учебный маркетплейс, объединяющий покупателей, продавцов,
курьеров и администрацию.

Проект предназначен для закрепления: - Django MVT --- понимание
архитектуры веб-приложений; - Django REST Framework --- API,
сериализаторы, аутентификация и permissions; - FastAPI --- создание
современного API; - SQLAlchemy --- ORM, модели и связи; - Pydantic ---
валидация данных.

**Основная идея:** пользователи находят товары, регистрируются,
добавляют товары в корзину и оформляют заказы. Желающие стать продавцами
или курьерами подают заявки. После одобрения администратором они
получают соответствующие возможности.

**Фирменная особенность:** пиксельный единорог, который сочетается с
цветовой палитрой платформы и используется как элемент бренда, а не как
множество декоративных стикеров.

Палитра основана на предоставленном референсе.

  Цвет            HEX         Использование
  --------------- ----------- -----------------------------------
  Alice Blue      `#D1E7F1`   Основной светлый фон
  Periwinkle      `#D5CAF5`   Дополнительные акценты
  Pearl Aqua      `#70C9B1`   Основные кнопки и выделения
  Pacific Cyan    `#3A879D`   Вторичные элементы
  Pine Teal       `#0C423F`   Текст, навигация, важные элементы
  Midnight Navy   `#0B062F`   Фон пиксельного единорога

### Правила дизайна

-   Светлый основной интерфейс.
-   Тёмно-зелёный цвет используется для текста, навигации и важных
    элементов.
-   Pearl Aqua --- основной цвет кнопок.
-   Periwinkle --- дополнительный акцент.
-   Pacific Cyan --- вторичные элементы.
-   Единорог используется в логотипе, приветственном блоке, пустых
    состояниях и, возможно, на странице загрузки.
-   Никаких розовых перегруженных интерфейсов.
-   **Никаких декоративных стикеров на карточках товаров.**
-   **Не добавлять стикеры/наклейки с надписями вроде «Продукт»,
    «Товар», «Новинка» поверх изображений.**
-   Карточки товаров должны быть чистыми и современными: фотография,
    название, цена, рейтинг (при наличии), кнопка.
-   Responsive design: desktop, tablet, mobile.

## 3. Языки платформы

Платформа поддерживает два языка: - Русский (`ru`) - Английский (`en`)

### Требования

1.  Пользователь может переключать язык.
2.  Названия категорий отображаются на выбранном языке.
3.  Основные кнопки, формы, ошибки и сообщения переводятся.
4.  Пользователь может выбрать язык при первом посещении.
5.  Выбранный язык сохраняется.

Примеры:

  Русский           English
  ----------------- ------------------
  Главная           Home
  Категории         Categories
  Поиск товаров     Search products
  Войти             Login
  Корзина           Cart
  Стать продавцом   Become a seller
  Стать курьером    Become a courier

При нажатии на товар пользователь открывает отдельную страницу.

На странице: - фотографии товара; - название; - цена; - описание; -

Пример:

``` text

Price: 250 TJS

Description:
High-quality wireless headphones with comfortable
design and long battery life.

Seller: TechStore

Quantity: [-] 1 [+]

[Add to Cart]
[Buy Now]
```

## 9. Регистрация и авторизация покупателей

### Регистрация

Поля: - номер телефона; - пароль; - подтверждение пароля.

Дополнительно: - имя; - фамилия --- можно добавить после регистрации.

### Требования

-   регистрация по номеру телефона;
-   пароль не должен быть чрезмерно сложным;
-   SMS-подтверждение на первом этапе необязательно;
-   вход по номеру телефона и паролю.

Пример:

``` text
Phone number: +992XXXXXXXXX
Password: ********

[Register]
```

### Безопасность

-   пароль хранится в хешированном виде;
-   пароль не хранится в открытом тексте;
-   используется безопасная аутентификация;
-   JWT или другая подходящая схема авторизации;
-   защищённые endpoints проверяют авторизацию.

------------------------------------------------------------------------

## 10. Корзина

Пользователь может: - добавлять товары; - удалять товары; - изменять
количество; - видеть общую сумму.

Пример:

``` text
Shopping Cart

Wireless Headphones — 250 TJS
Quantity: 2

Smart Watch — 400 TJS
Quantity: 1

Total: 900 TJS

[Checkout]
```

### Правила

-   нельзя добавить больше товаров, чем доступно на складе;
-   при изменении количества пересчитывается стоимость;
-   корзина сохраняется для авторизованного пользователя.

------------------------------------------------------------------------

## 11. Оформление заказа

После нажатия Checkout пользователь заполняет форму.

Поля: - имя; - номер телефона; - адрес доставки; - комментарий к
заказу; - способ оплаты.

На первом этапе можно реализовать оплату при получении (Cash on
Delivery).

### Статусы заказа

``` text
Pending
Confirmed
Processing
Shipped
Delivered
Cancelled
```

На первом этапе подключение реальных платежных систем необязательно.

## 12. Стать продавцом

Внизу сайта находится раздел **Become a Seller**.

Пользователь заполняет заявку.

### Форма продавца

-   имя;
-   фамилия;
-   номер телефона;
-   название магазина;
-   описание магазина;
-   адрес;
-   категория товаров;
-   дополнительная информация.

После отправки заявка получает статус `Pending`. Пока заявка не
одобрена, пользователь не может размещать товары.

### Одобрение заявки

Администратор видит заявки и может: - Approve; - Reject.

При одобрении: - заявка получает статус `Approved`; - пользователь
получает статус/роль Seller; - появляется Seller Dashboard; -
пользователь может создавать товары.

При отклонении: - статус `Rejected`; - доступ к Seller Dashboard не
предоставляется; - при необходимости пользователь может подать новую
заявку.

------------------------------------------------------------------------

## 13. Seller Dashboard

После одобрения продавец получает панель управления.

Разделы: - My Products; - Orders; - Store Information; - Statistics.

### My Products

Продавец может: - добавлять товары; - изменять товары; - удалять
товары; - менять цену; - менять количество; - загружать фотографии.

### Создание товара

Поля: - название; - описание; - цена; - категория; - количество; -
изображение; - бренд --- необязательно.

### Ограничения

Продавец управляет только собственными товарами. Он не может
редактировать, удалять или изменять цены чужих товаров. Создавать товары
могут только одобренные продавцы.

------------------------------------------------------------------------

## 14. Стать курьером

Внизу сайта находится раздел **Become a Courier**.

### Форма курьера

-   имя;
-   фамилия;
-   номер телефона;
-   адрес;
-   транспорт;
-   опыт работы;
-   дополнительная информация.

После отправки заявка получает статус `Pending`.

### Одобрение курьера

Администратор рассматривает заявку.

При одобрении: - пользователь получает роль Courier; - появляется
Courier Dashboard; - пользователь может получать назначенные доставки.

При отклонении: - пользователь не получает доступ к курьерской панели.

------------------------------------------------------------------------

## 15. Courier Dashboard

Курьер может: - просматривать назначенные доставки; - видеть адрес
доставки; - видеть номер телефона клиента; - видеть информацию о
заказе; - изменять статус доставки.

Статусы доставки:

``` text
Assigned
Picked Up
In Delivery
Delivered
```

Курьер не может самостоятельно назначать себе любые заказы. Заказы
назначаются администратором или системой.

Администратор управляет платформой.

### Пользователи

-   удалять категории.

-   назначать курьера.

## 20. Авторизация и Permissions

### Guest

Может: - просматривать товары; - просматривать категории; - искать
товары.

Не может: - оформлять заказы; - добавлять товары в корзину; - размещать
товары.

### Customer

Может: - пользоваться корзиной; - оформлять заказ; - просматривать свои
заказы; - подать заявку на продавца; - подать заявку на курьера.

### Seller

Может: - создавать товары; - редактировать собственные товары; - удалять
собственные товары; - просматривать собственные заказы.

### Courier

Может: - просматривать назначенные заказы; - изменять статус доставки.

### Admin

Может: - управлять всеми данными; - одобрять заявки; - назначать
курьеров; - управлять товарами и категориями.

**Проверка прав должна выполняться на backend, а не только скрытием
кнопок на frontend.**

## 26. Критерии готовности проекта

-   [ ] Пользователь может зарегистрироваться по номеру телефона.
-   [ ] Пользователь может авторизоваться.
-   [ ] Пользователь может переключать русский и английский языки.
-   [ ] На главной странице отображаются категории.
-   [ ] Работает поисковик товаров.
-   [ ] Можно фильтровать товары по категории и цене.
-   [ ] Можно открыть отдельную страницу товара.
-   [ ] Пользователь может добавить товар в корзину.
-   [ ] Пользователь может оформить заказ.
-   [ ] Пользователь может подать заявку на продавца.
-   [ ] Администратор может одобрить или отклонить заявку.
-   [ ] Только одобренный продавец может размещать товары.
-   [ ] Продавец может управлять собственными товарами.
-   [ ] Пользователь может подать заявку на курьера.
-   [ ] Администратор может одобрить или отклонить заявку курьера.
-   [ ] Курьер может видеть назначенные ему заказы.
-   [ ] Курьер может менять статус доставки.
-   [ ] Администратор может управлять пользователями, товарами,
    категориями и заказами.
-   [ ] Backend корректно проверяет права доступа.
-   [ ] Дизайн соответствует цветовой палитре.
-   [ ] Пиксельный единорог используется как фирменный элемент.
-   [ ] Карточки товаров не содержат декоративных стикеров.
-   [ ] Сайт корректно работает на мобильных устройствах.
